# one-c-form-compiler — руководство для ИИ-агента

Утилита правит **обычные формы 1С 8.3** (толстый клиент, профиль `FormElements27`):

* во внешних обработках `.epf` и отчётах `.erf`;
* в **формах конфигурации** в EDT-проекте (`Form.oform`), например в форме элемента справочника.

Внутренности формы (скобочный формат, якоря, счётчики id, порядок обхода, источники данных,
колонки таблиц, командные панели) утилита ведёт сама. Агент описывает, **что** изменить, —
командой или JSON-планом — и проверяет результат. Ключи ИИ не нужны.

Управляемые формы (`Form.form`) этой утилитой не правятся (для них есть, например, AI-EDT `edit_form`).

## Где форма

| Что правим | Вход | Запись |
|---|---|---|
| Внешняя обработка/отчёт | `<файл>.epf` / `.erf` | только в новый файл `-o` (входной не меняется) |
| Форма конфигурации | `--project <EDT-проект> --form <Тип>.<Объект>.<Форма>` или путь к `Form.oform` | на месте, с резервной копией (см. ниже); или в другой файл `-o <новый>.oform` (тогда входной не меняется и копия не нужна) |

Резервная копия при записи на месте:

* `Form.oform` лежит внутри EDT-проекта (выше по пути есть папка с `DT-INF` и `src`) — копия в
  `<проект>/.one-c-form-backups/<путь формы>.<дата-время>` (вне `src/`, EDT её не подхватывает);
* `Form.oform` передан напрямую и корня EDT-проекта над ним нет — копия рядом с файлом:
  `Form.oform.bak-<ГГГГММДД-ЧЧММСС>`.

Путь копии возвращается в `publish.backup`.

Имя формы конфигурации: `Catalog.Номенклатура.ФормаЭлемента`, `Document.Заказ.ФормаДокумента`,
`CommonForm.Имя`; можно по-русски (`Справочник.…`, `Документ.…`, `Обработка.…`, `Отчет.…`,
`РегистрСведений.…`, `ПланВидовХарактеристик.…`, `ОбщаяФорма.…` и др.).

Форма конфигурации записывается, только если сборка и повторный разбор совпали с правкой и
файл не изменился за время правки (иначе `E_INPUT_CHANGED`). **После записи** EDT должен
перечитать проект: F5 на проекте или AI-EDT `infobase_admin update_database` с
`refreshWorkspace=true` (он обновляет проект с диска; та же подсказка приходит в
`publish.refresh_hint`). Не правь форму, пока она открыта в редакторе EDT с несохранёнными
изменениями.

## Порядок работы

1. **Посмотреть форму:** `inspect <вход> --json`. В ответе:
   * `elements` — имя, тип, координаты, контейнер и страница, заголовок, привязка `data`
     (`data_bound: true` — элемент привязан к данным, даже если путь не удалось прочитать),
     обработчики `events`; у табличных полей — `columns` (имя, заголовок, ширина, `data`, события
     ячейки) и `value_table: true` для таблицы значений; у командных панелей — `command_panel`
     (`source` — табличное поле-источник действий или `<form>`, `autofill`, `buttons`: имя,
     заголовок и `standard` — код стандартного действия, `separator`, `submenu` или `procedure`);
     у полей ввода и табличных полей с флагом «Только просмотр» — `read_only: true`;
   * `pages` — паспорт стиля каждой страницы (`container` — имя панели, `page` — имя страницы):
     колонки подписей и полей, высоты, шаг строки, размер клиентской области;
   * `object_attributes` — реквизиты объекта (для форм конфигурации и стандартные: Код,
     Наименование, Владелец, Родитель / Номер, Дата);
   * `tabular_sections` — табличные части объекта и их реквизиты (для форм конфигурации);
   * `events` — какие события поддерживаются для каждого типа (`TableColumn` — события ячейки
     колонки, `Form` — события формы); `form_events` — уже назначенные события формы;
   * `languages` — языки заголовков формы; `known_issues` — несоответствия, которые были в форме
     до правки (утилита сравнивает с ними и не допускает новых).
2. **Составить план** по формату ниже. Геометрию обычно не указывай.
3. **Проверить без записи:** `apply <вход> --plan plan.json --dry-run --json`.
4. **Записать:** `apply <вход> --plan plan.json [-o <новый файл>] --json`.
5. **Проверить в 1С** (тестовая база из `ONE_C_FORM_1CV8` / `ONE_C_FORM_INFOBASE`):
   * EPF/ERF: `--runtime-check` или `runtime-check <новый файл> --json`;
   * форма конфигурации: сначала обнови тестовую базу из проекта (например, AI-EDT
     `infobase_admin update_database` с `refreshWorkspace=true`), затем
     `runtime-check --project <проект> --form <форма> --json`.

   `runtime-check --timeout <секунды>` — сколько ждать отчёта 1С (по умолчанию 180).
   Утилита открывает форму и сверяет элементы, размеры, заголовки, `Данные`, подключённые
   события, а у таблиц — колонки. `passed: true` — форма работает как задумано. Рабочую базу не
   обновляй и не проверяй: только тестовую.
6. **Сообщить пользователю:** что изменено (`changes`), куда записано, резервная копия,
   предупреждения (`warnings`), результат проверки в 1С, напоминание обновить проект в EDT.

Короткие команды с теми же полями: `add`, `modify`, `remove`, `title`, `size` (размер формы,
`--width`/`--height`; операция `set_form_size`), `add-column`, `modify-column`, `remove-column`.
Колонка двухколоночной шапки в `add` — `--layout-column 1|2` (в плане — `column`). Подробности — `one-c-form-compiler <команда> --help`.
Новая панель короткой командой: `add --type Panel --name <Имя> --page <Стр1> --page <Стр2>` (заголовки
страниц = имена; это операция `add_panel`); у остальных типов `--page` — страница, на которую ставится
элемент.

Только в плане (`apply --plan`), у коротких команд таких параметров нет:

* операции `add_page`, `remove_page`, `add_command_panel` (с `shift`), `add_button`, `remove_button`,
  `set_form_events`, `set_procedure`, `add_variable`; `add_panel` — с заголовками страниц и размещением
  на странице другой панели;
* поле `template` операции `add`;
* поле `checkbox` операции `add_column` (колонка-флажок);

Флаг «Только просмотр» поля ввода или табличного поля есть и у коротких команд: `add … --read-only`, `modify … --read-only` /
`--no-read-only` (в плане — `read_only`).
* многоязычные заголовки — объект `{"ru": "...", "uk": "..."}` в `caption` (у команд `--caption`
  принимает только строку).

## Образец для опытов

В исходниках проекта лежит `tests/fixtures/sample_ordinary.epf` — синтетическая внешняя
обработка `ПримерОбычнойФормы` с одной обычной формой «Корректировка записей регистров»
(650x363, 37 элементов). На ней можно опробовать все примеры EPF из этого руководства
(результат — в новый файл через `-o`, образец не меняется):

* `Надпись1`/`Номер`, `Надпись2`/`Дата`, `Надпись3`/`Комментарий`, `Надпись4`/`Ответственный` —
  надписи и поля (поля привязаны к реквизитам документа, которых в обработке нет: `data_bound:
  true` без `data`); примеры не опираются на реквизиты обработки, поэтому `data` в них нет;
* `ДействияФормы` (вверху) и `ОсновныеДействияФормы` (внизу) — командные панели формы;
* `ПанельРегистров` — панель со страницами `РегистрыНакопления`, `РегистрыСведений`,
  `РегистрыБухгалтерии`, `ЗаполнениеДвижений`, `РегистрыРасчета` и вложенными панелями;
* `ТабличноеПолеДвиженияБУ`/`НУ`/`МУ`/`Бюджетирование` с панелями `КоманднаяПанельБУ` и т. д.;
  табличное поле `ЗаполнениеДвижений` (колонки `НомерСтроки`, `Действие`, `Документ`,
  `Примечание`);
* надписи-гиперссылки `ГиперссылкаНастройкаСоставаРегистров…`; события формы `ПередОткрытием`,
  `ПриОткрытии`, `ОбновлениеОтображения` уже назначены.

```
one-c-form-compiler inspect tests/fixtures/sample_ordinary.epf --json
one-c-form-compiler apply tests/fixtures/sample_ordinary.epf --plan plan.json --dry-run --json
one-c-form-compiler apply tests/fixtures/sample_ordinary.epf --plan plan.json -o Out.epf --json
one-c-form-compiler add tests/fixtures/sample_ordinary.epf -o Out2.epf --type Field --name Скидка --label "Скидка, %:" --value-type "Число(5,2)" --width 120
one-c-form-compiler add-column tests/fixtures/sample_ordinary.epf -o Out3.epf --table ЗаполнениеДвижений --name Сумма --after Документ --width 80
```

## Формат плана

План — объект `{"operations": [...]}` (можно и просто массив операций). В плане не больше **100**
операций (иначе `E_PLAN_TOO_LARGE`). Неизвестное поле операции — ошибка `E_PLAN_FIELD`.

Пример для образца `sample_ordinary.epf` (проходит `apply --dry-run`):

```json
{"operations": [
  {"op": "add", "type": "Field", "name": "Скидка", "label": "Скидка, %:", "value_type": "Число(5,2)",
   "width": 120, "events": {"ПриИзменении": "СкидкаПриИзменении"}},
  {"op": "add", "type": "Button", "name": "Пересчитать", "caption": "Пересчитать", "beside": "Скидка",
   "handler": "ПересчитатьНажатие"},
  {"op": "modify", "name": "Надпись1", "caption": "Номер док.:"},
  {"op": "modify_column", "table": "ЗаполнениеДвижений", "name": "Примечание",
   "caption": {"ru": "Комментарий", "uk": "Коментар"}},
  {"op": "add_column", "table": "ЗаполнениеДвижений", "name": "Сумма", "after": "Документ", "width": 80},
  {"op": "remove", "name": "ПодсказкаРегистрыСведений3"},
  {"op": "set_title", "title": "Корректировка записей (пример)"},
```

не хватит места (`E_NO_SPACE`). Таблица на новой странице ставится с `top: 36`, чтобы над ней
сразу поместилась командная панель (24 + зазор 3); без `top` командная панель сама сдвинет таблицу
вниз (см. `add_command_panel`).

Привязка к данным — в форме конфигурации, где у объекта есть реквизиты и табличные части
(`object_attributes`, `tabular_sections` из `inspect`), например в форме документа с табличной
частью `Товары`:

```json
{"operations": [
  {"op": "add", "type": "Field", "name": "Скидка", "label": "Скидка, %:", "data": "Скидка"},

   "columns": ["НомерСтроки", "Номенклатура"], "container": "ОсновнаяПанель", "page": "Товары",
   "events": {"ПриВыводеСтроки": "ТоварыПриВыводеСтроки"}},
  {"op": "add_column", "table": "Товары", "name": "Цена", "data": "Цена", "after": "Номенклатура",
   "events": {"ПриИзменении": "ТоварыЦенаПриИзменении"}}

```

### Операция `add`

* `type` — `Label` | `Field` | `Button` | `CheckBox` | `Group` | `Table` (или Надпись, ПолеВвода,
  Поле, Кнопка, Флажок, Рамка, РамкаГруппы, ТабличноеПоле, Таблица). Панель добавляется операцией
  `add_panel` (`"type": "Panel"` в `add` — `E_TYPE_UNSUPPORTED`). `name` — идентификатор 1С,
  уникальный на форме.
* `caption` — текст элемента (строка или `{"ru": "...", "uk": "..."}`); `label` (только Field и
  Button) — надпись `Надпись<name>` слева от элемента в той же строке; где встаёт пара — см.
  «Строки и две колонки» ниже; `tooltip` — подсказка.
* `data`:
  * Field/CheckBox — реквизит из `object_attributes` (CheckBox — только Булево); тип поля берётся
    из реквизита;
  * Table — табличная часть из `tabular_sections` или реквизит формы типа «ТаблицаЗначений»;
    **без `data`** (только с `columns`) — свободное табличное поле типа «ТаблицаЗначений»: его
    заполняет модуль формы (`ЭлементыФормы.<Имя>.Значение = ТаблицаЗначений`), колонки привязаны
    к колонкам этой таблицы по имени (`Данные` = имя колонки).
* `columns` (Table) — список колонок: реквизиты табличной части и `НомерСтроки`; имя, которого нет
  в табличной части, даёт колонку без данных. Без `columns` — `НомерСтроки` и все реквизиты.
  У таблицы значений `columns` обязателен — это имена колонок таблицы значений.
* `value_type` (свободное Field): `Строка(N)`, `Число(D,F)`, `Дата`, `ДатаВремя`, `Булево`, `like:<Поле>`.
* `read_only` (Field и Table) — `true`/`false`: свойство «Только просмотр» (ТолькоПросмотр) поля ввода
  или табличного поля. Без `read_only` новый элемент редактируемый, даже если образец формы только для
  просмотра (с явным `template` флаг берётся из образца). У других типов — `E_TYPE_UNSUPPORTED` (у
  флажка обычной формы свойства ТолькоПросмотр нет; используй `Доступность` в модуле). Запись
  необычного формата — `E_PROPERTY_FORMAT` (флаг ставится в Конфигураторе).
  Пример: `{"op": "add", "type": "Field", "name": "Итог", "label": "Итог:", "value_type": "Число(15,2)",
  "width": 120, "read_only": true}`.
* `handler` — основное событие (Нажатие для Button/Label, ПриИзменении для Field/CheckBox).
* `events` — `{"Событие": "Процедура"}`:
  * Field: ПриИзменении, НачалоВыбора, НачалоВыбораИзСписка, ОбработкаВыбора;
  * CheckBox: ПриИзменении; Button и Label: Нажатие;
  * Table: ПриАктивизацииСтроки, ПередНачаломДобавления, ПередНачаломИзменения, ПередУдалением,
    ПриНачалеРедактирования, ПередОкончаниемРедактирования, ПриОкончанииРедактирования,
    ПриИзмененииФлажка, ПриВыводеСтроки, ПослеУдаления, ОбработкаВыбора, ПриПолученииДанных.

  Заглушки процедур с правильными параметрами добавляются в модуль формы, если процедуры ещё нет.
* `template` — имя существующего элемента того же типа, внешний вид которого надо скопировать.
  Элемента с таким именем нет — `E_ELEMENT_NOT_FOUND`; элемент другого типа — `E_TEMPLATE_TYPE`.
  Без `template` берётся самый типичный элемент этого типа на форме, а если такого нет —
  встроенный нейтральный шаблон; если и встроенного шаблона для типа нет — `E_TEMPLATE_MISSING`.
* Размещение: `container`/`page` (панель и страница), `beside`, `column`, `left`/`top`/`width`/`height`.
  Без них элемент встаёт новой строкой под содержимым, над нижним блоком (итоги, командная
  панель внизу) — по паспорту стиля страницы; поле — шириной колонки полей, таблица и рамка — во
  всю ширину, высота таблицы 150. Если места нет, форма или панель верхнего уровня растягиваются
  (вложенная панель — нет, `E_NO_SPACE`). Ширина надписи, флажка и кнопки подбирается по тексту.
* Явные `left`/`top`/`width`/`height` за пределами клиентской области (ниже или правее формы) тоже
  растягивают форму:
  * по высоте — открывается полоса над нижней полосой элементов, прижатых к низу (командная панель
    `ОсновныеДействияФормы`): она уходит под новый элемент (зазор — шаг строк страницы), всё, что выше,
    остаётся на месте;
  * по ширине — форма становится шириной «правый край элемента + 8», элементы, привязанные к правому
    краю, сдвигаются или растягиваются (как в `set_form_size`).

  Панель верхнего уровня растёт только по высоте; на вложенной панели и за правым краем панели —
  по-прежнему `E_GEOMETRY_OUTSIDE`. Явная `width` при явном `left` не обрезается по клиентской области.
* `stretch` — `"width"` | `"height"` | `"both"`: как элемент ведёт себя при изменении размера формы.
  * Без `stretch` элемент сохраняет размер: верхний и нижний края привязаны к верхней границе
    контейнера (или к нижней, если элемент встал под элементом, растягивающимся по высоте, например
    под таблицей, — тогда он сдвигается вместе с низом формы), левый и правый — к левой.
  * `"width"` — правый край привязан к правой границе контейнера: ширина растёт вместе с формой.
  * `"height"` — верхний край привязан к верхней границе, нижний — к нижней: растёт высота.
  * `"both"` — и то и другое (типично для таблицы на отдельной странице).

  `stretch` задаётся в `add` и `add_panel` (в командной строке — `add --stretch`); в `modify` это поле
  отклоняется (`E_PLAN_FIELD`).
* Порядок обхода: новая надпись, поле, кнопка или флажок, вставшие в строку правее существующих
  элементов (`beside`, `column`, `top`), идут в обходе сразу после самого правого из них (по строкам, как
  в шапках типовых форм); в новой строке — последними на странице.
* Пустая страница (например, только что созданная `add_page` или страница новой панели): её размер —
  клиентская область панели, как у соседних страниц: из привязок элементов других страниц, иначе из
  направляющих страницы (правая/нижняя направляющая + её отступ), иначе из размера панели минус рамка
  закладок (2 по ширине, 20 по высоте; у панели без закладок — 0).
  Паспорт стиля пустой страницы — значения по умолчанию: подписи с x = 8 (ширина 84), поля с
  x = 96 (ширина 120), высота строки 19, шаг строки 24; первая строка — у верхнего края с зазором 5,
  таблица и рамка — от x = 8 на всю ширину минус отступы.

#### Строки и две колонки

Шапку в две колонки («Номер + Дата» слева, «Наименование» справа) строят без пикселей. Пример для
образца (проходит `apply tests/fixtures/sample_ordinary.epf --plan plan.json --dry-run --json`):

```json
{"operations": [
  {"op": "add", "type": "Field", "name": "Сумма", "label": "Сумма:", "value_type": "Число(15,2)",
   "beside": "Дата", "width": 100},
  {"op": "add", "type": "Field", "name": "Организация", "label": "Организация:", "value_type": "Строка(50)",
   "column": 1},
  {"op": "add", "type": "Field", "name": "Наименование", "label": "Наименование:",
   "value_type": "Строка(100)", "column": 2, "beside": "Организация"},
  {"op": "add", "type": "Field", "name": "Склад", "label": "Склад:", "value_type": "Строка(50)", "column": 1},
  {"op": "add", "type": "Field", "name": "Контрагент", "label": "Контрагент:", "value_type": "Строка(50)",
   "column": 2, "beside": "Склад"}
]}
```

* `label` + `beside: <элемент>` — пара встаёт в строку этого элемента справа от него: надпись через 4 px
  (шириной по тексту), поле через 4 px после надписи (ширина — `width` или колонка полей страницы, но не
  дальше правого отступа 8). Так к «Номер» добавляют «Дата».
* `column`: `1` — левая половина страницы, `2` — правая (граница — клиентская ширина / 2):
  * надпись колонки 2 встаёт от середины страницы, поле — со смещением колонки полей страницы
    (`field_left − label_left` из `pages`; если надпись длиннее — через 4 px после неё) и выравнивается по
    полям, уже стоящим в этой колонке; оно тянется до правого отступа 8 (или шириной `width`);
  * в колонке 1 поле не заходит дальше «середина − 12»;
  * строка — строка `beside` (с `column` элемент `beside` задаёт только строку), иначе `top`, иначе новая
    строка под содержимым;
  * `column` работает и без `label`: надпись, поле, кнопка, флажок, рамка, таблица — в своей половине.
* Поле в колонке 2 без `width` и без `stretch` получает `"stretch": "width"`: правый край привязан к правой
  границе контейнера, как у правого поля шапок типовых форм; с явной `width` поле не растягивается.
  Остальные края — к левой/верхней границе, как у любого нового элемента.
* `label` + `left`/`top` — надпись в этой точке (недостающая координата — как по умолчанию), поле после
  неё со смещением колонки полей.
* Пара или элемент с `beside` + `label`, `column`, `left`/`top` + `label` не должны налезать на существующие
  элементы — иначе `E_NO_SPACE` (возьми другую строку или колонку). `column` не 1/2 — `E_PLAN_FIELD`;
  страница слишком узка для двух колонок — `E_NO_SPACE`.

### Колонки: `add_column`, `modify_column`, `remove_column`

* Общие поля: `table` — имя табличного поля, `name` — имя колонки.
* `add_column`: `data` (реквизит табличной части или `НомерСтроки`; путь через точку — см. ниже; без
  `data` — колонка без данных), `caption` (по умолчанию — `data`, у пути через точку — его последнее
  имя), `width` (4..2000), `after` (по умолчанию — в конец), `events`, `checkbox` (только в плане).
* `modify_column`: `caption`, `width`, `data`, `events`.
* События колонки (ячейки): ПриИзменении, НачалоВыбора, НачалоВыбораИзСписка, ОбработкаВыбора.
* `remove_column`: без `"force": true` отклоняется, если модуль обращается к колонке
  (`…Колонки.<Имя>`). Сначала поправь код; force — только по прямой просьбе пользователя.
* `data` колонок: у таблицы на табличной части — реквизит табличной части; у таблицы значений —
  имя колонки таблицы значений (по умолчанию = `name`).
* `"checkbox": true` — колонка-флажок:
  * у таблицы значений имя колонки пишется в `ДанныеФлажка`, а не в `Данные` (для колонок типа Булево);
  * у таблицы на табличной части `data` обязателен (`E_DATA_REQUIRED`) и должен быть реквизитом типа
    Булево (иначе `E_DATA_TYPE`): он пишется в `ДанныеФлажка`, `Данные` пусты, своего элемента ячейки у
    колонки нет (флажок рисует и переключает сама таблица; так устроено большинство таких колонок в
    типовых конфигурациях), поэтому `events` у колонки нет (`E_HANDLER_UNSUPPORTED`) — реакцию на
    флажок пиши в событии таблицы `ПриИзмененииФлажка`. `modify_column` с `data` меняет `ДанныеФлажка`.
    В ответе и в `inspect` у колонки `checkbox: true` и `data` — имя реквизита.

  ```json
  {"op": "add_column", "table": "Товары", "name": "Отметка", "data": "Отметка", "checkbox": true,
   "width": 30, "after": "НомерСтроки"}
  ```
* Путь через точку в `data` (`"ЗаказКлиента.Контрагент"`, `"Номенклатура.Родитель.Наименование"`) — только
  у таблицы на табличной части в форме конфигурации EDT-проекта. Каждое звено, кроме последнего, —
  реквизит со ссылочным типом на один объект (`СправочникСсылка.X`, `ДокументСсылка.Y` …); утилита
  читает `.mdo` этих объектов (их реквизиты и стандартные `Код`, `Наименование`, `Номер`, `Дата`). В
  обычных формах типовых конфигураций колонок с таким путём в `Данные` нет: колонка без данных
  заполняется в `ПриВыводеСтроки`. Утилита делает так же: колонка без `Данные` и без своего элемента
  ячейки (только просмотр), её тип — тип последнего реквизита, а в начало обработчика `ПриВыводеСтроки`
  таблицы (если его нет — назначается `<Таблица>ПриВыводеСтроки` с заглушкой) добавляется строка

  ```
  ОформлениеСтроки.Ячейки.<Колонка>.УстановитьТекст(Строка(ДанныеСтроки.<путь>)); // one-c-form-compiler: <Таблица>.<Колонка> = <путь>
  ```

  (имена параметров берутся из объявления обработчика). `remove_column` удаляет эту строку вместе с
  колонкой. В ответе и в `inspect` у такой колонки `computed: "<путь>"` вместо `data`. Ошибки: звена
  нет — `E_DATA_UNKNOWN`; звено не ссылка на один объект (примитив, составной тип) — `E_DATA_TYPE`;
  таблица значений, EPF/ERF (нет метаданных конфигурации), флажок, `modify_column` — `E_DATA_UNSUPPORTED`;
  `events` — `E_HANDLER_UNSUPPORTED`.

  ```json
  {"op": "add_column", "table": "Товары", "name": "Контрагент", "data": "ЗаказКлиента.Контрагент",
   "width": 150}
  ```
* Тип ячейки колонки таблицы значений — Строка (так устроены такие колонки в типовых
  конфигурациях). Если в ячейке нужен выбор ссылки, задай тип в модуле:
  `Колонки.Номенклатура.ЭлементУправления.ТипЗначения = Новый ОписаниеТипов("СправочникСсылка.Номенклатура")`.

### Командная панель: `add_command_panel`

Добавляет командную панель (КоманднаяПанель) **над существующим табличным полем**; источник
действий панели — это табличное поле.

```json
{"op": "add_command_panel", "name": "КоманднаяПанельИтоги", "table": "ТаблицаИтогов",
 "autofill": true,
 "buttons": [{"name": "Заполнить", "procedure": "КоманднаяПанельИтогиЗаполнить",
              "caption": "Заполнить", "tooltip": "Заполнить таблицу итогов"}]}
```

* `name` (обязательно) — имя новой панели, уникальное на форме; `table` (обязательно) — имя
  табличного поля (не таблица — `E_TYPE_UNSUPPORTED`).
* `autofill` (по умолчанию `true`) — автозаполнение: стандартные кнопки таблицы (Добавить,
  Удалить и т. д.) платформа выводит сама. С `"autofill": false` на панели только то, что
  перечислено в `standard` и `buttons`.
* `standard` — только при `"autofill": false` (иначе `E_PLAN_FIELD`): массив стандартных действий из
  `Добавить`, `Скопировать`, `Изменить`, `Удалить`, `ПереместитьВверх`, `ПереместитьВниз`.
* `buttons` — массив `{"name", "procedure", "caption"?, "tooltip"?}`: кнопки, вызывающие процедуру
  модуля формы. `name` уникален в панели (`E_NAME_EXISTS`); `caption` по умолчанию = `name`,
  `tooltip` по умолчанию = `caption`. В модуль добавляется заглушка `Процедура <procedure>(Кнопка)`,
  если процедуры ещё нет; принятое в Конфигураторе имя — `<ИмяПанели><ИмяКнопки>`. Перед своими
  кнопками ставится разделитель.
* `height` (16..60, по умолчанию 24) и `gap` (0..20, по умолчанию 3) — высота панели и зазор до
  таблицы; вне диапазона — `E_GEOMETRY_INVALID`.
* Панель занимает ширину таблицы и встаёт над ней: низ панели = верх таблицы − `gap`. Левый и правый
  края привязаны к контейнеру так же, как у таблицы; в порядке обхода панель идёт сразу после таблицы.
* `shift` (по умолчанию `true`): если над таблицей нет места (мешает элемент выше — например, надпись
  над таблицей — или верх страницы), таблица и всё, что на её странице начинается не выше её верха,
  сдвигаются вниз ровно настолько, чтобы панель встала с зазором `gap` под элементом выше. Сначала
  используется свободное место внизу страницы; если его нет, форма или панель верхнего уровня
  растягиваются (как при `add`), элементы, прижатые к низу (`ОсновныеДействияФормы`), уходят вниз.
  Размеры и привязки сдвинутых элементов сохраняются. На вложенной панели без свободного места —
  `E_NO_SPACE`. С `"shift": false` — прежнее поведение: нет места — `E_NO_SPACE`.
* Результат: `name`, `table`, `rect`, `autofill`, `standard`, `buttons`, `shifted` (на сколько пикселей
  сдвинута таблица; 0 — место было).

Пример для образца (проходит `apply --dry-run`): надпись, таблица прямо под ней и панель — таблица
сдвинется на 25 px, форма станет выше:

```json
{"operations": [
  {"op": "add", "type": "Label", "name": "НадписьСтроки", "caption": "Строки документа:"},
  {"op": "add", "type": "Table", "name": "Строки", "columns": ["Товар", "Количество"], "height": 120},
  {"op": "add_command_panel", "name": "КоманднаяПанельСтроки", "table": "Строки", "shift": true}
]}
```
* Кнопки в уже существующие панели (в том числе в панели формы) — операция `add_button` (ниже); панель
  без табличного поля не создаётся. После добавления панели проверь форму через `runtime-check`.

### Кнопки командных панелей: `add_button`, `remove_button`

Кнопка в **существующей** командной панели формы — например `ДействияФормы` (вверху) или
`ОсновныеДействияФормы` (внизу) образца, или панель табличного поля (`КоманднаяПанельБУ`). Пример для
образца (проходит `apply tests/fixtures/sample_ordinary.epf --plan plan.json --dry-run --json`):

```json
{"operations": [
  {"op": "add_button", "panel": "ДействияФормы", "name": "Пересчитать", "caption": "Пересчитать",
   "tooltip": "Пересчитать движения", "procedure": "ДействияФормыПересчитать", "separator": true},
  {"op": "add_button", "panel": "ОсновныеДействияФормы", "name": "Проверить",
   "procedure": "ОсновныеДействияФормыПроверить", "before": "Действие"},
  {"op": "add_button", "panel": "КоманднаяПанельБУ", "name": "УдалитьСтроку", "standard": "Удалить"},
  {"op": "remove_button", "panel": "ДействияФормы", "name": "Разделитель4"}
]}
```

* `add_button`:
  * `panel` (обязательно) — имя командной панели (`command_panel` в `inspect`); не панель —
    `E_TYPE_UNSUPPORTED`, нет такого элемента — `E_ELEMENT_NOT_FOUND`;
  * `name` (обязательно) — имя кнопки, уникальное в панели (`E_NAME_EXISTS`, сверяй с `buttons` в
    `inspect`, включая кнопки подменю);
  * ровно одно из: `procedure` — процедура модуля формы (в модуль добавляется заглушка
    `Процедура <procedure>(Кнопка)`, если её нет; принятое имя — `<ИмяПанели><ИмяКнопки>`), или
    `standard` — стандартное действие таблицы (`Добавить`, `Скопировать`, `Изменить`, `Удалить`,
    `ПереместитьВверх`, `ПереместитьВниз`; только у панели, источник действий которой — табличное поле,
    иначе `E_TYPE_UNSUPPORTED`). Ни одного или оба — `E_PLAN_FIELD`;
  * `caption` — текст кнопки (строка или `{"ru": "...", "uk": "..."}`), по умолчанию = `name` (у
    стандартного действия — его заголовок, например `&Удалить`); `tooltip` — подсказка, по умолчанию =
    `caption`;
  * `before` или `after` — имя кнопки верхнего уровня панели, перед/после которой встать (не оба —
    `E_PLAN_FIELD`; нет такой — `E_ELEMENT_NOT_FOUND`); по умолчанию — в конец панели;
  * `separator: true` — перед кнопкой ещё и разделитель (имя `Разделитель`, `Разделитель1`, … —
    первое свободное в панели);
  * картинка не задаётся; кнопка показывается текстом (режим отображения берётся у соседней кнопки, если
    у той «Авто» или «Надпись»);
  * результат: `panel`, `name`, `position` (индекс кнопки среди кнопок верхнего уровня), `procedure`
    или `standard`, `separator` (имя добавленного разделителя).
* `remove_button`: `panel`, `name` (кнопка или разделитель, на любом уровне меню), необязательно
  `"force": true`. Без `force` отклоняется (`E_ELEMENT_REFERENCED`), если модуль обращается к кнопке
  (`…Кнопки.<Имя>`). Подменю не удаляется (`E_TYPE_UNSUPPORTED` — это Конфигуратор). Процедура кнопки в
  модуле остаётся. Результат: `panel`, `name`, `kind` (`button` / `separator`).
* Панель в незнакомом формате (несогласованная запись кнопок) — `E_PANEL_FORMAT`: кнопки этой панели
  правят в Конфигураторе. Формат — `docs/command-panel-format.md` в исходниках.
* `runtime-check` сверяет, что каждая кнопка верхнего уровня панели есть в `Кнопки` открытой формы.

### Панель: `add_panel`

Новая панель (Панель) с закладками и пустыми страницами. Пример для образца (проходит
`apply tests/fixtures/sample_ordinary.epf --plan plan.json --dry-run --json`):

```json
{"operations": [
  {"op": "add_panel", "name": "ПанельПроверки", "stretch": "both",
   "pages": [{"name": "Первая", "caption": "Первая"}, {"name": "Вторая", "caption": {"ru": "Вторая", "uk": "Друга"}}]},
  {"op": "add", "type": "Label", "name": "НадписьПервая", "caption": "Текст на первой странице",
   "container": "ПанельПроверки", "page": "Первая"},
  {"op": "add", "type": "Table", "name": "ТаблицаВторая", "columns": ["Колонка1", "Колонка2"],
   "container": "ПанельПроверки", "page": "Вторая", "stretch": "both"}
]}
```

* `name` (обязательно) — имя панели, уникальное на форме (`E_NAME_EXISTS`).
* `pages` (обязательно, 1..N) — страницы по порядку: строка-имя или `{"name", "caption"}`; `caption` —
  строка или `{"ru": "...", "uk": "..."}`, по умолчанию = имя. Пустой список или неверный элемент —
  `E_PLAN_FIELD`; имя не идентификатор 1С — `E_NAME_INVALID`; одно имя дважды — `E_NAME_EXISTS`.
* `container`/`page` — где поставить панель: на форме (по умолчанию) или на странице другой панели
  (вложенная панель).
* `left`/`top`/`width`/`height` — по умолчанию как у таблицы: новая строка под содержимым страницы,
  во всю ширину минус отступы, высота 150; форма или панель верхнего уровня растягиваются, вложенная
  панель — нет (`E_NO_SPACE`). Меньше 40x50 — `E_GEOMETRY_INVALID`; вне клиентской области —
  `E_GEOMETRY_OUTSIDE`.
* `stretch` — как у `add` (`"both"` — панель растёт вместе с формой).
* Панель с закладками сверху, страницы пустые; клиентская область страницы — размер панели минус
  2 по ширине и 20 по высоте. Элементы на страницы ставятся обычным `add` (и `add_page`,
  `add_command_panel`) с `"container": <панель>, "page": <страница>`.
* Порядок обхода — как у других добавляемых элементов: панель последняя на своей странице.
* Результат: `name`, `container`, `page`, `rect`, `stretch`, `pages` (`name`, `caption`).
* Запись панели берётся из встроенного шаблона (типичная панель типовой конфигурации); формат —
  `docs/panel-format.md` в исходниках. После добавления проверь форму через `runtime-check`.

### Размер формы: `set_form_size`

Пример для образца (проходит `apply --dry-run`): форма 650x363 → 750x450, затем поле ниже клиентской
области — форма вырастет до 519 по высоте (нижняя командная панель уйдёт под поле):

```json
{"operations": [
  {"op": "set_form_size", "width": 750, "height": 450},
  {"op": "add", "type": "Field", "name": "Примечание", "value_type": "Строка(100)", "left": 8, "top": 470,
   "width": 300}
]}
```

* `width`, `height` — новая клиентская ширина/высота формы в пикселях (хотя бы одно, иначе
  `E_PLAN_FIELD`; целые 50..3000, иначе `E_GEOMETRY_INVALID`). Короткая команда:
  `size <вход> --width 750 --height 450`.
* Элементы ведут себя по привязкам, как в 1С при изменении размера формы:
  * край, привязанный к правой или нижней границе формы, сдвигается вместе с ней (растягивающиеся
    таблицы и панели растут, нижняя командная панель и прижатые к низу элементы уходят вниз);
  * край, привязанный к другому элементу, следует за ним; непривязанный край остаётся на месте;
  * панель, изменившая размер, так же раскладывает свои страницы (и сдвигает их направляющие);
  * командная панель без привязок, закреплённая внизу, идёт с низом; на всю ширину — растягивается.
* Уменьшение, при котором элемент вышел бы за свой контейнер, схлопнулся или налез на другой, —
  `E_GEOMETRY_INVALID`, форма не меняется (типовая форма обычно уже минимальна: уменьшение даже на
  несколько пикселей часто невозможно).
* Результат: `width`, `height`, `previous` (`width`, `height`), `moved` — элементы, у которых изменился
  прямоугольник.

### `modify`, `remove`, `set_title`

* `modify`: `name` и любые из `caption`, `tooltip`, `left`, `top`, `width`, `height`, `value_type`,
  `data`, `handler`, `events` (для таблиц — события табличного поля), `read_only` (Field и Table). Других полей нет: `stretch`,
  `template`, `label` и т. п. дают `E_PLAN_FIELD`.
* `remove`: `name`, необязательно `"force": true` (как у колонок). Удаляются надписи, поля ввода,
  кнопки, флажки, рамки, разделители, картинки, переключатели, поля выбора, индикаторы, командные
  панели, а также:
  * табличное поле — вместе с колонками и командными панелями, у которых оно источник действий;
  * панель — со всеми страницами и всем, что на них (включая вложенные панели и командные панели
    удаляемых таблиц).

  Без `force` удаление отклоняется (`E_ELEMENT_REFERENCED`), если модуль обращается
  (`ЭлементыФормы.<Имя>`) к удаляемому элементу или к любому из удаляемых вместе с ним. Кнопку формы
  по умолчанию удалить нельзя и с `force`. Элементы, привязанные к удалённому, перепривязываются к
  контейнеру. В результате — `also_removed`: что удалено вместе с элементом.
* `set_title`: `title` — непустая строка.

### Закладки, события формы, код модуля

* `add_page`: `container` (панель), `name`, `caption` — новая страница (закладка) в конце панели.
  Элементы на неё ставятся обычным `add` с `"container": <панель>, "page": <name>`. Размер страницы —
  клиентская область панели (как у соседних страниц).
* `remove_page`: `container` (панель), `page`, необязательно `"force": true`. Без `force`
  отклоняется (`E_ELEMENT_REFERENCED`), если на странице есть элементы или модуль обращается к ней
  (`Страницы.<page>`); с `force` элементы страницы удаляются (как `remove` с `force`). Последнюю
  страницу панели удалить нельзя (`E_PLAN_FIELD` — удали панель). Результат: `container`, `page`,
  `removed` (удалённые элементы).
* `set_form_events`: `events` — `{"Событие": "Процедура"}`. События формы: ПередОткрытием,
  ПриОткрытии, ПередЗакрытием, ПриЗакрытии, ОбработкаВыбора, ОбработкаЗаписиНовогоОбъекта,
  ОбработкаОповещения, ПриПовторномОткрытии, ОбновлениеОтображения, ВнешнееСобытие. События записи
  объекта ПередЗаписью, ПриЗаписи(Отказ), ПослеЗаписи — только в форме элемента справочника.
  Заглушки процедур добавляются в модуль.
* `set_procedure`: `name`, `text` — одна процедура или функция целиком (`Процедура …` …
  `КонецПроцедуры`; перед ней допустимы только комментарии и директивы `&…`). Заменяет одноимённый
  метод модуля (в том числе заглушку) или добавляется после последнего метода. В JSON перевод
  строки пиши как `\n`, табуляцию — `\t`. Так пишется код модуля обычной формы конфигурации.
* `add_variable`: `name` — объявляет переменную модуля `Перем <name>;` перед первым методом (после
  уже объявленных переменных). Если переменная уже объявлена, модуль не меняется (`added: false`).

## Ошибки и что делать

Ответ с ошибкой (с `--json`, в том числе при ошибке разбора командной строки):
`{"status":"error","code":...,"message":...}`. Без `--json` — строка `Ошибка <код>: <текст>` в
stderr (например, `Ошибка E_USAGE: --output is required (or use --dry-run)`); ошибка разбора
параметров без `--json` печатается как подсказка `usage:` и текст ошибки. В ошибке плана указан
номер операции (`operation #N`). План применяется целиком или не применяется вовсе.

Коды выхода:

* `0` — успешно (в том числе `runtime-check` с `passed: true`);
* `2` — ошибка использования (`E_USAGE`: неверные параметры командной строки);
* `3` — ошибка формы или плана;
* `4` — ошибка файла, v8unpack, сборки или окружения, включая `E_RUNTIME_CONFIG` и
  `E_INTERNAL`;
* `5` — ошибка встроенного ИИ (`ai`);
* `6` — проверка в 1С не пройдена: расхождения, `timeout` или ошибка запуска проверки.

Коды `E_SOURCE_INVALID`, `E_PROFILE_UNSUPPORTED`, `E_SERIALIZATION_MALFORMED`, `E_PATCH_INVALID`,
`E_BACKEND_FAILURE`, `E_PROVIDER_FAILURE`, `E_OUTPUT_FAILURE`, `E_CONTRACT_VIOLATION` и
`E_PARSER_*` (`core/errors.py`) — внутренние коды разборщика скобочного формата; командная
строка их не возвращает (в команде `ai` такая ошибка становится `E_AI_CANDIDATE_INVALID`).

`warnings` — не ошибка, но требует внимания (например, основной реквизит формы другого объекта).

`runtime-check` сверяет у колонок таблиц ширину в символах с учётом шрифта таблицы (масштаб —
по медиане колонок таблицы; допуск ±2 символа или ±12 % у широких колонок: платформа пересчитывает
пиксели в символы по шрифту таблицы, и колонка 154 px бывает и 24, и 22 символа), у колонок-флажков —
`ДанныеФлажка`; у полей ввода — «Только просмотр»; у командных панелей — что кнопки панели есть в
`Кнопки`. Тестовая база — файловая
(`ONE_C_FORM_INFOBASE` — каталог базы). Пользователь тестовой базы — `ONE_C_FORM_INFOBASE_USER`
(пароль — в переменной, имя которой в `ONE_C_FORM_INFOBASE_PASSWORD_ENV`); у пользователя должна
быть снята «Защита от опасных действий», иначе при каждом запуске появляется окно.

`runtime-check`: `timeout` значит, что за `--timeout` секунд (по умолчанию 180) отчёт не пришёл —
обычно платформа показала модальное окно (ошибка модуля, блокировка базы, предупреждение
безопасности при открытии внешней обработки). Сообщи пользователю, не повторяй проверку в цикле.

## Ограничения

* Нельзя добавлять картинки, переключатели, поля выбора; командная панель добавляется
  только над табличным полем (`add_command_panel`); в существующие командные панели добавляются
  кнопки и разделители (`add_button`), но не подменю и не картинки кнопок. Новая панель — всегда с
  закладками сверху.
* «Только просмотр» задаётся только у полей ввода (у флажков и таблиц — кодом модуля).
* Колонка с путём через точку — только для просмотра (текст в `ПриВыводеСтроки`), только в формах
  конфигурации EDT-проекта.
* Страница добавляется только в конец панели; последнюю страницу панели удалить нельзя.
* Видимость колонок не меняется; события колонки — только у колонок со своим элементом ячейки.
* Вложенные панели не растягиваются автоматически; панель верхнего уровня растёт только по высоте
  (ширину меняет только `set_form_size` у всей формы).
* Двухколоночная разметка — только половины страницы (`column` 1/2); новые элементы привязываются к
  контейнеру (как все добавляемые), а не друг к другу, как бывает в типовых формах.
* Поддерживаются только перечисленные события.
* В одном плане не больше 100 операций.
* Профиль элементов только FormElements27; проверено на платформе 8.3.27.
* Страницы без имени или с повторяющимся именем называются в `inspect` и в плане `#<номер>` или
  `<имя>#<номер>` (номер — позиция страницы с нуля; `#` в именах 1С не бывает): `"page": "#0"`,
  `--page "#0"`. В самой форме имена страниц не меняются.
* При открытии форма приводит в порядок учёт идентификаторов: счётчик id не ниже наибольшего id
  элемента; записи привязок (у элементов и в индексе панелей) удалённых элементов убираются. В файл
  это попадает только вместе с правкой и перечисляется в `repairs` ответа `--json` (и строками `! исправлено при загрузке` без `--json`). Новый
  элемент получает id больше всех id, упомянутых в форме (элементы, привязки, источники данных,
  источники действий командных панелей, кнопка по умолчанию).
* EPF/ERF: при открытии формы контейнер один раз пересобирается без правок (около секунды) — формы
  должны вернуться байт в байт, иначе `E_FORM_ROUNDTRIP`. `Form.oform` проверяется так же при открытии
  (`E_OFORM_ROUNDTRIP`); оставшиеся отказы называются кодами `E_FORM_DUPLICATE_NAMES`,
  `E_FORM_EMPTY_NAME`, `E_FORM_PROP_NAME` (6 из 3695 форм типовой конфигурации).
