# 1c-ai-form-compiler

[English version](README.md) · [Російська версія](README.ru.md)

`one-c-form-compiler` — утиліта командного рядка для Windows, яка редагує **звичайні форми
1С:Підприємства 8.3** (товстий клієнт, профиль элементов `FormElements27`):

* у зовнішніх обробках і звітах (`.epf` / `.erf`);
* в **формах конфигурации в EDT-проєкте** (`Forms/<Форма>/Form.oform`), например в форме
  елемента довідника.

Зміну описують параметрами команды или JSON-планом: элементы, прив'язка до даних,
обробники подій, табличні поля та їхні колонки, командные панели, закладки, код модуля форми.
Усі внутрішні перехресні посилання форми утиліта підтримує сама. Результат можно открыть в
**тестовій** базі 1С і переконатися, що платформа показує форму як задумано.

Утиліта розрахована на роботу з ІІ-агентами (Claude Code, Codex и др.) **без ключей API**: агент
виконує `one-c-form-compiler guide`, читає правила й сам складає план.

Керовані форми не підтримуються.

## Можливості

* `inspect` — элементы с координатами, страницы и их паспорт стиля, привязки к данным, события,
  колонки таблиц, командные панели, реквизиты и табличные части объекта.
* Добавление, изменение и удаление элементов: надписи, поля ввода, кнопки, флажки, рамки,
  табличные поля. Без явной геометрии элемент ставится в стиле страницы; форма или панель
  верхнего уровня при необходимости растягиваются (и для явных координат ниже или правее формы).
* Строки и шапка в две колонки без пикселей: пара «надпись + поле» справа от элемента (`label` +
  `beside`), в левой или правой половине страницы (`column`: 1/2, правое поле растягивается с формой)
  или в точке `left`/`top`; порядок обхода — по строкам.
* Размер формы (`set_form_size`, `size --width/--height`): элементы ведут себя по привязкам, как в 1С
  (нижняя командная панель, растягивающиеся панели и таблицы, страницы панелей); уменьшение меньше
  содержимого отклоняется.
* Привязка полей и флажков к реквизитам; табличные поля на табличных частях, на реквизитах формы
  типа «ТаблицаЗначений» или свободные таблицы значений, заполняемые модулем.
* «Только просмотр» полей ввода и табличных полей (`read_only`, `--read-only`).
* Колонки таблиц: добавление, изменение, удаление; колонки-флажки таблиц значений и табличных частей
  (реквизит Булево в `ДанныеФлажка`); колонки с путём через точку (`ЗаказКлиента.Контрагент`) — по
  метаданным EDT-проєкта, текст в `ПриВыводеСтроки`; события ячеек.
* Обработчики событий элементов, таблиц, колонок и формы — с заглушками процедур в модуле.
* Командная панель над табличным полем (если над таблицей нет места, таблица и всё под ней
  сдвигаются вниз): автозаполнение, стандартные действия, кнопки с процедурами модуля; кнопки и разделители в существующих командных панелях, в том числе в панелях
  формы (`add_button`, `remove_button`).
* Новые панели с закладками (`add_panel`, также `add --type Panel --page …`), новые закладки панели;
  удаление закладок (`remove_page`), панелей со всем содержимым и табличных полей вместе с их
  командными панелями; привязка `stretch` для элементов, растущих вместе с формой.
* Код модуля: замена или добавление процедуры/функции целиком, объявление переменных модуля.
* JSON-план «всё или ничего» (до 100 операций) со стабильными кодами ошибок.
* Проверка в толстом клиенте 1С на тестовой базе.
* Необязательная встроенная команда `ai` (запрос словами → план) для работы без агента.

## Вимоги

Лише Windows.

| Функція | Що потрібно |
|---|---|
| Усе (з вихідників) | Python 3.14 и `v8unpack==1.2.13` (тягне `tqdm` и `colorama`) |
| Всё (релізна збірка) | Ничего: Python и v8unpack уже в пакеті |
| `runtime-check`, `--runtime-check` | Толстый клиент 1С:Предприятие 8.3 (`1cv8.exe`) и **тестова файлова база** |
| Форми конфігурації | EDT-проєкт на диске; для проверки в 1С — тестовая база, оновлена з проєкту |
| Команда `ai` (необов'язково) | Провайдер `anthropic` (или `claude`): Python-SDK `anthropic` (`pip install -e ".[claude]"`; в релизную сборку не входит) и ключ API или учётные данные SDK. Провайдер `openai`: ключ OpenAI API (встроенный HTTPS-клиент к OpenAI Responses API, без SDK) |

Перевірено на платформі 8.3.27 и v8unpack 1.2.13.

## Встановлення

### A. Релизная сборка (Python не потрібен)

1. Завантажте `one-c-form-compiler-<версия>-win-x64.zip` (контрольная сумма — в `SHA256SUMS.txt`) и
   розпакуйте в любую теку, например `C:\Tools`. В архиве одна папка верхнего уровня:

   ```
   C:\Tools\one-c-form-compiler-<версия>-win-x64\
     LICENSE, README.md, README.ru.md, THIRD_PARTY_NOTICES.txt, set-env.example.cmd
     one-c-form-compiler\one-c-form-compiler.exe   (+ папка _internal рядом с ним)
   ```

2. Відкрийте `cmd` или PowerShell в папке
   `C:\Tools\one-c-form-compiler-<версия>-win-x64\one-c-form-compiler` и виконайте
   `one-c-form-compiler.exe doctor`.
3. За бажанням добавьте эту теку в `PATH`.

В папке верхнего уровня — лицензия (`LICENSE`), инструкция пользователя (`README.ru.md` /
`README.md`), пример настройки переменных `set-env.example.cmd` и `THIRD_PARTY_NOTICES.txt`.

### B. Из исходников

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -e ".[test]"
.venv\Scripts\one-c-form-compiler doctor
```

Если `doctor` сообщает, что v8unpack нет: `.venv\Scripts\python -m pip install v8unpack==1.2.13`.

## Швидкий старт

Примеры для EPF выполняются как есть на синтетическом образце `tests/fixtures/sample_ordinary.epf`
(обработка `ПримерОбычнойФормы`, одна обычная форма «Корректировка записей регистров», 37
элементов: `Надпись1`/`Номер`, `Надпись2`/`Дата`, панель `ПанельРегистров` со страницами,
табличное поле `ЗаполнениеДвижений` и др.). Входной файл не меняется, каждая команда пишет новый.

```powershell
copy tests\fixtures\sample_ordinary.epf Sample.epf

# Что на форме (элементы, координаты, страницы, паспорт стиля)
one-c-form-compiler inspect Sample.epf
one-c-form-compiler inspect Sample.epf --json

# Поле с надписью слева новой строкой в стиле формы (--width 120 — чтобы справа поместилась кнопка)
one-c-form-compiler add Sample.epf -o Out1.epf --type Field --name Скидка --label "Скидка, %:" --value-type "Число(5,2)" --width 120
# Кнопка справа от него с заглушкой обработчика в модуле
one-c-form-compiler add Out1.epf -o Out2.epf --type Кнопка --name Пересчитать --caption Пересчитать --beside Скидка --handler ПересчитатьНажатие

# Изменить, удалить, сменить заголовок
one-c-form-compiler modify Sample.epf -o Out3.epf --name Надпись1 --caption "Номер док.:"
one-c-form-compiler remove Sample.epf -o Out4.epf --name ПодсказкаРегистрыСведений3
one-c-form-compiler title  Sample.epf -o Out5.epf "Корректировка записей (пример)"

# Колонки табличного поля
one-c-form-compiler add-column    Sample.epf -o Out6.epf --table ЗаполнениеДвижений --name Сумма --after Документ --width 80
one-c-form-compiler modify-column Sample.epf -o Out7.epf --table ЗаполнениеДвижений --name Примечание --caption Комментарий

# План: проверить без записи, затем записать в новый файл
one-c-form-compiler apply Sample.epf --plan plan.json --dry-run --json
one-c-form-compiler apply Sample.epf --plan plan.json -o Out8.epf --json

# Форма конфигурации в EDT-проєкте (правится на месте, копия в <проект>\.one-c-form-backups)
one-c-form-compiler inspect --project C:\path\to\edt-project --form Catalog.Номенклатура.ФормаЭлемента --json
one-c-form-compiler apply   --project C:\path\to\edt-project --form Catalog.Номенклатура.ФормаЭлемента --plan plan.json --json
```

`plan.json` для образца — поле с обработчиком, новая страница панели `ПанельРегистров` со
свободной таблицей значений, растущей вместе с формой, командная панель над ней и заголовок:

```json
{"operations": [
  {"op": "add", "type": "Field", "name": "Скидка", "label": "Скидка, %:", "value_type": "Число(5,2)",
   "width": 120, "events": {"ПриИзменении": "СкидкаПриИзменении"}},
  {"op": "add_page", "container": "ПанельРегистров", "name": "Итоги", "caption": "Итоги"},
  {"op": "add", "type": "Table", "name": "ТаблицаИтогов", "columns": ["Показатель", "Значение"],
   "container": "ПанельРегистров", "page": "Итоги", "top": 36, "stretch": "both"},
  {"op": "add_command_panel", "name": "КоманднаяПанельИтоги", "table": "ТаблицаИтогов",
   "buttons": [{"name": "Заполнить", "procedure": "КоманднаяПанельИтогиЗаполнить"}]},
  {"op": "set_title", "title": "Корректировка записей (пример)"}
]}
```

Привязка к данным (`"data": "<реквизит>"`, табличное поле на табличной части) требует объекта
с реквизитами — обычно это форма конфигурации; пример есть в `guide`.

Порядок работы: `inspect --json` → план → `apply --dry-run` → `apply` → `runtime-check`.
Полный формат плана, коды ошибок и ограничения печатает `one-c-form-compiler guide`.

Коды выхода:

| Код | Значение |
|---|---|
| `0` | успешно (для `runtime-check` — `passed: true`) |
| `2` | ошибка использования (`E_USAGE`): неверная командная строка, например `apply` для EPF без `-o` и без `--dry-run` |
| `3` | ошибка формы или плана (имена, геометрия, неподдерживаемая операция, …) |
| `4` | ошибка файла, v8unpack, сборки или окружения, в том числе нет входного файла или файла плана (`E_INPUT_MISSING`), `E_RUNTIME_CONFIG` и `E_INTERNAL` |
| `5` | ошибка встроенной команды `ai` |
| `6` | проверка в 1С не пройдена: расхождения, `timeout` или ошибка запуска проверки |

Ошибка печатается в stderr как `Ошибка <код>: <текст>`, а с `--json` — в stdout как
`{"status": "error", "code": ..., "message": ...}` (в том числе ошибки командной строки).
Все коды и что с ними делать — в `one-c-form-compiler guide`.

### Форми конфігурації

* Форма задаётся как `--project <EDT-проєкт> --form <Тип>.<Объект>.<Форма>` (типы по-английски
  или по-русски: `Catalog`/`Справочник`, `Document`/`Документ`, `CommonForm`/`ОбщаяФорма`, …)
  или путём к `Form.oform`.
* `Form.oform` правится **на месте** с резервной копией:
  * внутри EDT-проєкта (выше по пути есть папка с `DT-INF` и `src`) — в
    `<проект>/.one-c-form-backups/<путь формы>.<дата-время>` (вне `src/`, EDT её не подхватывает);
  * `Form.oform`, переданный напрямую без корня EDT-проєкта над ним, — рядом с файлом:
    `Form.oform.bak-<ГГГГММДД-ЧЧММСС>`.

  Путь копии возвращается в `publish.backup`. Можно записать и в другой файл: `-o new.oform` —
  тогда входной файл не меняется и копия не нужна.
* Запись виконуєся, только если пересобранная форма совпала с правкой и файл не менялся во
  время правки (`E_INPUT_CHANGED`).
* После записи обновите проект в EDT: F5 на проекте или AI-EDT `infobase_admin update_database`
  с `refreshWorkspace=true` (та же подсказка приходит в `publish.refresh_hint`). Не правьте
  форму, открытую в EDT с несохранёнными изменениями.
* Перед `runtime-check --project …` обновите **тестовую** базу из проекта (в EDT или через AI-EDT
  `infobase_admin update_database` с `refreshWorkspace=true`).
* `runtime-check --timeout <секунды>` — сколько ждать отчёта 1С (по умолчанию 180).

## Змінні середовища

Утилита читает **только настоящие переменные окружения**, файлы `.env` она не загружает.
Список переменных — в `.env.example` (исходники) и `set-env.example.cmd` (релиз).

| Переменная | Для чего | Значение |
|---|---|---|
| `ONE_C_FORM_1CV8` | `runtime-check` | Полный путь к `1cv8.exe` |
| `ONE_C_FORM_INFOBASE` | `runtime-check` | Каталог **тестовой файловой базы** |
| `ONE_C_FORM_INFOBASE_USER` | `runtime-check` | Пользователь базы (необов'язково) |
| `ONE_C_FORM_INFOBASE_PASSWORD_ENV` | `runtime-check` | **Имя** другой переменной, в которой лежит пароль |
| `ONE_C_FORM_V8UNPACK` | все команды | Необязательный путь к внешнему исполняемому v8unpack |
| `ONE_C_FORM_AI_PROVIDER` | `ai` | `anthropic` (или `claude`) либо `openai` |
| `ONE_C_FORM_AI_MODEL` | `ai` | Модель; для `anthropic` по умолчанию `claude-opus-5-5`, для `openai` обязательна |
| `ONE_C_FORM_AI_API_KEY_ENV` | `ai` | **Имя** переменной с ключом API; по умолчанию `ANTHROPIC_API_KEY` / `OPENAI_API_KEY` |
| `ONE_C_FORM_AI_TIMEOUT_SECONDS` | `ai` | Таймаут запроса в секундах: больше 0 и не больше 300. По умолчанию 30; пока `ONE_C_FORM_AI_MAX_OUTPUT_TOKENS` не задана, команда `ai` поднимает таймаут минимум до 120 (вместе с лимитом ответа 16000 токенов) |
| `ONE_C_FORM_AI_MAX_INPUT_BYTES` | `ai` | Лимит описания формы для модели (256000) |
| `ONE_C_FORM_AI_MAX_OUTPUT_BYTES` | `ai` | Лимит ответа модели (64000) |
| `ONE_C_FORM_AI_MAX_OUTPUT_TOKENS` | `ai` | Лимит выходных токенов (16000, если не задана; заданное значение используется как есть, и таймаут тогда не поднимается) |

Пароль базы передаётся `1cv8.exe` в командной строке (`/P`) и виден другим процессам на этом
компьютере. Используйте отдельного тестового пользователя с одноразовым паролем и снимите у него
«Защиту от опасных действий», иначе при каждом запуске появляется окно.

## Гарантії безпасності

* Входной `.epf`/`.erf` не открывается на запись; результат пишется в новый файл атомарно,
  хеш входного файла перепроверяется перед публикацией.
* Результат публикуется, только если пересобранный контейнер разбирается ровно в отредактированную
  форму и вне неё ничего не изменилось.
* `Form.oform` пишется на месте только после такой же проверки, с резервной копией и только если
  файл не менялся во время правки.
* План применяется целиком или не применяется; после каждой операции проверяется целостность
  формы.
* Элемент или колонку, на которые ссылается модуль, без `force` удалить нельзя.
* `runtime-check` работает с одноразовой копией; зонд ничего не записывает и не проводит.
  Утилита завершает только запущенный ею процесс `1cv8` и никогда не обновляет конфигурацию базы.

## Обмеження

* Только обычные формы, профиль `FormElements27`.
* Нельзя добавлять картинки, переключатели, поля выбора; командная панель — только над
  табличным полем; в существующие командные панели добавляются кнопки и разделители, но не подменю
  и не картинки кнопок. «Только просмотр» — только у полей ввода и табличных полей.
* Страница добавляется в конец панели; последнюю страницу панели удалить нельзя (удаляется панель).
* Видимость колонок не меняется; вложенные панели не растягиваются автоматически.
* Небольшую долю форм конфигурации (в основном регламентированные отчёты) нельзя пересобрать без
  изменений — такие формы утилита не правит (`E_OFORM_ROUNDTRIP`).
* `runtime-check` нужны файловая база и товстий клієнт; модальное окно в 1С завершает проверку
  с `timeout`.

## Робота з ІІ-агентами

Скажите агенту перед правкой формы выполнить `one-c-form-compiler guide`
(`one-c-form-compiler.exe guide` для релизной сборки) и следовать этому руководству. Это
единственный источник правил для агента: порядок работы, формат плана, коды ошибок и что с ними
делать, ограничения. Ключи API не нужны.
