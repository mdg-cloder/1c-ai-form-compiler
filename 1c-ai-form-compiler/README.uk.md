# 1c-ai-form-compiler

[English version](README.md) · [Російська версія](README.ru.md)

`one-c-form-compiler` — утиліта командного рядка для Windows, яка редагує **звичайні форми
1С:Підприємства 8.3** (товстий клієнт, профіль елементів `FormElements27`):

* у зовнішніх обробках і звітах (`.epf` / `.erf`);
* у **формах конфігурації в EDT-проєкті** (`Forms/<Форма>/Form.oform`), наприклад у формі
  елемента довідника.

Зміну описують параметрами команди або JSON-планом: елементи, прив’язка до даних, обробники
подій, табличні поля та їхні колонки, командні панелі, закладки, код модуля форми. Утиліта
сама підтримує всі внутрішні перехресні посилання форми. Результат можна відкрити в **тестовій**
базі 1С і переконатися, що платформа показує форму як задумано.

Утиліта розрахована на роботу з ІІ-агентами (Claude Code, Codex тощо) **без ключів API**: агент
виконує `one-c-form-compiler guide`, читає правила й сам складає план.

Керовані форми не підтримуються.

## Можливості

* `inspect` — елементи з координатами, сторінки та їхній паспорт стилю, прив’язки до даних, події,
  колонки таблиць, командні панелі, реквізити та табличні частини об’єкта.
* Додавання, зміна та видалення елементів: написи, поля вводу, кнопки, прапорці, рамки,
  табличні поля. Без явної геометрії новий елемент ставиться в стилі сторінки; форма або панель
  верхнього рівня за потреби розтягується (так само для явних координат нижче або праворуч від форми).
* Рядки та шапка в два стовпці без пікселів: пара «напис + поле» праворуч від елемента (`label` +
  `beside`), у лівій або правій половині сторінки (`column`: 1/2, праве поле тягнеться з формою)
  або в точці `left`/`top`; порядок обходу — по рядках.
* Розмір форми (`set_form_size`, `size --width/--height`): елементи поводяться за прив’язками, як у 1С
  (нижня командна панель, панелі й таблиці з розтягуванням, сторінки панелей); зменшення менше за
  вміст відхиляється.
* Прив’язка полів і прапорців до реквізитів; табличні поля на табличних частинах, на реквізитах
  форми типу «ТаблицяЗначень» або вільні таблиці значень, які заповнює модуль форми.
* «Тільки перегляд» полів вводу та табличних полів (`read_only`, `--read-only`).
* Колонки таблиць: додавання, зміна, видалення; колонки-прапорці таблиць значень і табличних частин
  (реквізит Булево в `ДанныеФлажка`); колонки зі шляхом через крапку (`ЗаказКлиента.Контрагент`) —
  за метаданими EDT-проєкту, текст у `ПриВыводеСтроки`; події комірок.
* Обробники подій елементів, таблиць, колонок і форми — із заглушками процедур у модулі.
* Командна панель над табличним полем (якщо над таблицею немає місця, таблиця й усе під нею зсувається
  вниз): автозаповнення, стандартні дії, кнопки з процедурами модуля; кнопки й роздільники в існуючих
  командних панелях, зокрема панелях форми (`add_button`, `remove_button`).
* Нові панелі з закладками (`add_panel`, також `add --type Panel --page …`), нові закладки панелі;
  видалення закладок (`remove_page`), панелей з усім вмістом і табличних полів разом із їхніми
  командними панелями; прив’язка `stretch` для елементів, що ростуть разом із формою.
* Код модуля: заміна або додавання процедури/функції цілком, оголошення змінних модуля.
* JSON-план «увесь або нічого» (до 100 операцій) зі стабільними кодами помилок.
* Перевірка в товстому клієнті 1С на тестовій базі.
* Необов’язкова вбудована команда `ai` (запит словами → план) для роботи без агента.

## Вимоги

Лише Windows.

| Функція | Що потрібно |
|---|---|
| Усе (з вихідників) | Python 3.14 і `v8unpack==1.2.13` (тягне `tqdm` і `colorama`) |
| Усе (релізна збірка) | Нічого: Python і v8unpack уже в пакеті |
| `runtime-check`, `--runtime-check` | Товстий клієнт 1С:Підприємства 8.3 (`1cv8.exe`) і **тестова файлова база** |
| Форми конфігурації | EDT-проєкт на диску; для перевірки в 1С — тестова база, оновлена з проєкту |
| Команда `ai` (необов’язково) | Провайдер `anthropic` (псевдонім `claude`): Python SDK `anthropic` (`pip install -e ".[claude]"`; у реліз не входить) і ключ API або облікові дані SDK. Провайдер `openai`: ключ OpenAI API (вбудований HTTPS-клієнт до OpenAI Responses API, без SDK) |

Перевірено на платформі 8.3.27 і v8unpack 1.2.13.

## Встановлення

### A. Релізна збірка (Python не потрібен)

1. Завантажте `one-c-form-compiler-<версія>-win-x64.zip` з [релізів](https://github.com/mdg-cloder/1c-ai-form-compiler/releases)
   (контрольна сума — у `SHA256SUMS.txt`) і розпакуйте в будь-яку теку, наприклад `C:\Tools`. У
   архіві одна тека верхнього рівня:

   ```
   C:\Tools\one-c-form-compiler-<версія>-win-x64\
     LICENSE, README.md, README.ru.md, README.uk.md, THIRD_PARTY_NOTICES.txt, set-env.example.cmd
     one-c-form-compiler\one-c-form-compiler.exe   (+ теку _internal поруч)
   ```

2. Відкрийте `cmd` або PowerShell у теці
   `C:\Tools\one-c-form-compiler-<версія>-win-x64\one-c-form-compiler` і виконайте
   `one-c-form-compiler.exe doctor`.
3. За бажанням додайте цю теку в `PATH`.

У теці верхнього рівня — ліцензія (`LICENSE`), інструкції (`README.md`, `README.ru.md`,
`README.uk.md` у вихідниках), приклад змінних `set-env.example.cmd` і `THIRD_PARTY_NOTICES.txt`.

### B. З вихідників

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -e ".[test]"
.venv\Scripts\one-c-form-compiler doctor
```

`doctor` показує версії Python і v8unpack і чи налаштовані `runtime-check` та `ai`. Якщо v8unpack
відсутній: `.venv\Scripts\python -m pip install v8unpack==1.2.13`.

## Швидкий старт

Приклади для EPF працюють на синтетичному зразку `tests/fixtures/sample_ordinary.epf` (обробка
`ПримерОбычнойФормы`, одна звичайна форма «Корректировка записей регистров», 37 елементів:
`Надпись1`/`Номер`, `Надпись2`/`Дата`, панель `ПанельРегистров` зі сторінками, табличне поле
`ЗаполнениеДвижений` тощо). Вхідний файл не змінюється; кожна команда пише новий.

```powershell
copy tests\fixtures\sample_ordinary.epf Sample.epf

# Що на формі (елементи, координати, сторінки, паспорт стилю)
one-c-form-compiler inspect Sample.epf
one-c-form-compiler inspect Sample.epf --json

# Поле з написом зліва в новому рядку в стилі форми (--width 120 — місце для кнопки праворуч)
one-c-form-compiler add Sample.epf -o Out1.epf --type Field --name Скидка --label "Скидка, %:" --value-type "Число(5,2)" --width 120
# Кнопка праворуч із заглушкою обробника в модулі
one-c-form-compiler add Out1.epf -o Out2.epf --type Кнопка --name Пересчитать --caption Пересчитать --beside Скидка --handler ПересчитатьНажатие

# Змінити, видалити, заголовок
one-c-form-compiler modify Sample.epf -o Out3.epf --name Надпись1 --caption "Номер док.:"
one-c-form-compiler remove Sample.epf -o Out4.epf --name ПодсказкаРегистрыСведений3
one-c-form-compiler title  Sample.epf -o Out5.epf "Корректировка записей (пример)"

# Колонки табличного поля
one-c-form-compiler add-column    Sample.epf -o Out6.epf --table ЗаполнениеДвижений --name Сумма --after Документ --width 80
one-c-form-compiler modify-column Sample.epf -o Out7.epf --table ЗаполнениеДвижений --name Примечание --caption Комментарий

# Форма конфігурації в EDT-проєкті (правка на місці, копія в <проєкт>\.one-c-form-backups)
one-c-form-compiler inspect --project C:\path\to\edt-project --form Catalog.Номенклатура.ФормаЭлемента --json
one-c-form-compiler apply   --project C:\path\to\edt-project --form Catalog.Номенклатура.ФормаЭлемента --plan plan.json --dry-run --json
```

Поширені параметри: `--form <ім’я>` (форма всередині EPF/ERF з кількома формами або повне ім’я з
`--project`), `--dry-run` (перевірити без запису), `-o/--output`, `--overwrite`, `--json`.
У кожної команди є `--help`.

### Порядок роботи

1. `inspect <вхід> --json` — прочитати форму.
2. Скласти план (`plan.json`). Повний формат друкує `one-c-form-compiler guide`.
3. `apply <вхід> --plan plan.json --dry-run --json` — перевірити без запису.
4. `apply <вхід> --plan plan.json [-o <вихід>] --json` — записати.
5. `runtime-check <вихід> --json` (EPF/ERF) або `runtime-check --project <проєкт> --form <форма> --json`.

Невеликий план для зразка:

```json
{"operations": [
  {"op": "add", "type": "Field", "name": "Скидка", "label": "Скидка, %:", "value_type": "Число(5,2)",
   "width": 120, "events": {"ПриИзменении": "СкидкаПриИзменении"}},
  {"op": "add_page", "container": "ПанельРегистров", "name": "Итоги", "caption": "Итоги"},
  {"op": "add", "type": "Table", "name": "ТаблицаИтогов", "columns": ["Показатель", "Значение"],
   "container": "ПанельРегистров", "page": "Итоги", "top": 36, "stretch": "both"},
  {"op": "add_command_panel", "name": "КоманднаяПанельИтоги", "table": "ТаблицаИтогов",
   "buttons": [{"name": "Заполнить", "procedure": "КоманднаяПанельИтогиЗаполнить"}]},
  {"op": "set_title", "title": "Корректировка записей (пример)"}
]}
```

Прив’язка до даних (`"data": "<реквізит>"`, табличне поле на табличній частині) потребує об’єкта з
реквізитами — зазвичай це форма конфігурації; приклад є в `guide`.

Коди виходу:

| Код | Значення |
|---|---|
| `0` | успіх (для `runtime-check` — `passed: true`) |
| `2` | помилка використання (`E_USAGE`): невірний рядок команди, напр. `apply` для EPF без `-o` і без `--dry-run` |
| `3` | помилка форми або плану (імена, геометрія, непідтримувана операція, …) |
| `4` | помилка файла, v8unpack, збірки або середовища, зокрема відсутній вхід або план (`E_INPUT_MISSING`), `E_RUNTIME_CONFIG`, `E_INTERNAL` |
| `5` | помилка вбудованої команди `ai` |
| `6` | перевірка в 1С не пройдена: розбіжності, `timeout` або помилка під час перевірки |

Помилка виводиться в stderr як `Ошибка <код>: <текст>`, а з `--json` — у stdout як
`{"status": "error", "code": ..., "message": ...}` (також для помилок командного рядка).
Усі коди та дії — у `one-c-form-compiler guide`.

### Форми конфігурації

* Форма задається як `--project <EDT-проєкт> --form <Тип>.<Об’єкт>.<Форма>` (типи англійською
  або російською: `Catalog`/`Справочник`, `Document`/`Документ`, `DataProcessor`/`Обработка`,
  `CommonForm`/`ОбщаяФорма`, …) або шляхом до `Form.oform`.
* `Form.oform` правиться **на місці** з резервною копією:
  * у межах EDT-проєкту (вище по шляху є `DT-INF` і `src`) — у
    `<проєкт>/.one-c-form-backups/<шлях форми>.<мітка часу>` (поза `src/`, EDT її не підхоплює);
  * `Form.oform`, переданий напряму без кореня EDT-проєкту, — поруч із файлом:
    `Form.oform.bak-<РРРРММДД-ГГХХСС>`.

  Шлях копії повертається в `publish.backup`. Можна записати в інший файл `-o new.oform` — тоді
  вхід не змінюється і копія не створюється.
* Запис лише якщо перезібрана форма збігається з правкою і файл не змінювався під час редагування
  (`E_INPUT_CHANGED`).
* Після запису оновіть проєкт в EDT: F5 на проєкті або AI-EDT `infobase_admin update_database`
  з `refreshWorkspace=true` (підказка також у `publish.refresh_hint`). Не редагуйте форму, відкриту
  в EDT з незбереженими змінами.
* Перед `runtime-check --project …` оновіть **тестову** базу з проєкту (в EDT або через AI-EDT
  `infobase_admin update_database` з `refreshWorkspace=true`).
* `runtime-check --timeout <секунди>` — скільки чекати звіт від 1С (за замовчуванням 180).

## Змінні середовища

Утиліта читає **лише справжні змінні середовища**; файли `.env` не завантажує. Довідник змінних —
у `.env.example` (вихідники) та `set-env.example.cmd` (реліз).

| Змінна | Для чого | Значення |
|---|---|---|
| `ONE_C_FORM_1CV8` | `runtime-check` | Повний шлях до `1cv8.exe` |
| `ONE_C_FORM_INFOBASE` | `runtime-check` | Тека **тестової файлової бази** |
| `ONE_C_FORM_INFOBASE_USER` | `runtime-check` | Користувач бази (необов’язково) |
| `ONE_C_FORM_INFOBASE_PASSWORD_ENV` | `runtime-check` | **Ім’я** іншої змінної, де лежить пароль |
| `ONE_C_FORM_V8UNPACK` | усі команди | Необов’язковий шлях до зовнішнього v8unpack |
| `ONE_C_FORM_AI_PROVIDER` | `ai` | `anthropic` (псевдонім `claude`) або `openai` |
| `ONE_C_FORM_AI_MODEL` | `ai` | Ідентифікатор моделі; для `anthropic` за замовчуванням `claude-opus-5-5`, для `openai` обов’язково |
| `ONE_C_FORM_AI_API_KEY_ENV` | `ai` | **Ім’я** змінної з ключем API; за замовчуванням `ANTHROPIC_API_KEY` / `OPENAI_API_KEY` |
| `ONE_C_FORM_AI_TIMEOUT_SECONDS` | `ai` | Таймаут запиту в секундах: > 0 і ≤ 300. За замовчуванням 30; поки не задано `ONE_C_FORM_AI_MAX_OUTPUT_TOKENS`, команда `ai` підвищує таймаут щонайменше до 120 (разом із лімітом відповіді 16000 токенів) |
| `ONE_C_FORM_AI_MAX_INPUT_BYTES` | `ai` | Ліміт опису форми для моделі (256000) |
| `ONE_C_FORM_AI_MAX_OUTPUT_BYTES` | `ai` | Ліміт відповіді моделі (64000) |
| `ONE_C_FORM_AI_MAX_OUTPUT_TOKENS` | `ai` | Ліміт вихідних токенів (16000, якщо не задано; явне значення використовується як є, таймаут тоді не підвищується) |

Пароль бази передається `1cv8.exe` в командному рядку (`/P`) і видимий іншим процесам на цій
машині. Використовуйте окремого тестового користувача з одноразовим паролем і зніміть у нього
«Захист від небезпечних дій», інакше при кожному запуску з’являється вікно попередження.

## Гарантії безпеки

* Вхідний `.epf`/`.erf` не відкривається на запис; результат пишеться в новий файл атомарно,
  SHA-256 вхідного перепровіряється перед публікацією.
* Результат публікується лише якщо перезібраний контейнер розбирається рівно в відредаговану
  форму і поза нею нічого не змінилося (інакше `E_VERIFY_*`).
* `Form.oform` пишеться на місці лише після такої ж перевірки, з копією, і лише якщо файл не
  змінювався під час правки (`E_INPUT_CHANGED`).
* План «увесь або нічого». Після кожної операції зіставляється цілісність форми; операцію, що
  порушить узгодженість, відхилено (`E_INTEGRITY`).
* Елемент або колонку, на які посилається модуль, без `force` видалити не можна.
* `runtime-check` працює з одноразовою копією; зонд лише читає форму, нічого не зберігає й не
  проводить; для форм конфігурації форму навіть не відкриває. Утиліта завершує лише запущений нею
  процес `1cv8` і ніколи не оновлює конфігурацію бази.
* Усі дочірні процеси без оболонки, з лімітами часу й виводу.

## Обмеження

* Лише звичайні форми, профіль `FormElements27`; керовані форми не підтримуються.
* Не можна додавати зображення, перемикачі, поля вибору; командну панель можна додати лише над
  табличним полем; у наявні панелі — кнопки й роздільники, не підменю й не зображення кнопок.
  «Тільки перегляд» — лише для полів вводу й табличних полів.
* Нова сторінка додається в кінець панелі; останню сторінку панелі не видалити (видаляють панель).
* Видимість колонок не змінюється; вкладені панелі автоматично не ростуть.
* Лише задокументовані події (див. `guide`).
* Невелику частку форм конфігурації (переважно регламентовані звіти) неможливо перезібрати
  байт-в-байт — утиліта їх не править (`E_OFORM_ROUNDTRIP`).
* `runtime-check` потребує файлової бази й товстого клієнта; модальне вікно в 1С завершує перевірку
  з `timeout`.

## Робота з ІІ-агентами

Перед правкою форми агент має виконати `one-c-form-compiler guide` (`one-c-form-compiler.exe guide`
у релізі) і дотримуватися цього посібника. Це єдине джерело правил: порядок роботи, формат плану,
коди помилок і дії, обмеження. Ключі API не потрібні — агент сам пише плани й перевіряє їх через
`--dry-run` і `runtime-check`.

## Як працює редагування

v8unpack розкладає контейнер форми в JSON (заголовок, коренева панель, джерела даних, записи
елементів). `core/ordinary_form.py` править ці записи напряму й зберігає узгодженість усіх
перехресних посилань платформи: лічильник id, зв’язки ребер і зворотні списки, індекс прив’язок
панелей, щільний tab/z-порядок на сторінці, джерела даних, шляхи в `copyinfo`, кнопка за
замовчуванням і розмір форми. Нові елементи копіюють найтиповіший вигляд того ж типу на формі;
вбудовані нейтральні шаблони (`core/ordinary_templates.json`) — для форм без потрібного типу.

Нотатки про формати: [табличні поля](docs/table-format.md), [командні панелі](docs/command-panel-format.md),
[панелі](docs/panel-format.md), [поля вводу](docs/field-format.md).
Рішення про дизайн: [ADR-003](docs/adr/ADR-003-json-model-edit-plans.md),
[ADR-004](docs/adr/ADR-004-config-ordinary-forms.md).

## Збірка релізу

```powershell
powershell -ExecutionPolicy Bypass -File packaging\build_release.ps1 [-Python <python 3.14>] [-OutDir <тека>]
```

Скрипт створює середовище `.venv-build`, встановлює пакет і PyInstaller, збирає one-folder
дистрибутив з `packaging/one-c-form-compiler.spec` (виконуваний файл і середовище, без `.py`;
Anthropic SDK не входить). У теці виходу (за замовчуванням `dist`) — програма, `LICENSE`, файли з
`packaging/release/`, архів `one-c-form-compiler-<версія>-win-x64.zip` і `SHA256SUMS.txt`.

## Тести

```powershell
.venv\Scripts\python -m unittest discover -s tests -t . -p "test_*.py"
```

Тести, що потребують реальної звичайної форми, використовують `tests/fixtures/sample_ordinary.epf`
і пропускаються, якщо файлу немає; без v8unpack відповідні тести теж пропускаються.
